BUILD INSTRUCTIONS

Node 24, which is what CI builds and verifies the checksum on.

    git clone https://github.com/ArloL/configurable-containers
    cd configurable-containers
    git checkout v{{version}}
    npm ci
    BUILD_TIMESTAMP={{timestamp}} npm run package -- {{package_args}}

dist/configurable-containers-{{version}}.xpi then matches the submitted file byte
for byte — not a signed copy, which is repacked.

esbuild bundles three TypeScript entry points into background.js, options.js and
choice.js, unminified. The only other edit is the version, plus the id, name and
update_url on the dev channel.

WHAT IT DOES

Routes each site into a Firefox container per a YAML config the user edits in the
options page; unmatched sites open in a fresh temporary container.

PERMISSIONS

- webRequest, webRequestBlocking, <all_urls> — the mechanism. A blocking
  onBeforeRequest listener on main_frame decides the container; if it differs the
  request is cancelled and the tab reopened there. It must block because the
  decision precedes the request, and any domain may be routed.
- cookies — Firefox requires it for tabs.create({ cookieStoreId }), which
  otherwise throws. Also used by the optional cookie-seeding feature.
- contextualIdentities, tabs — create/query/remove containers and tabs.
- storage — storage.local holds the config; the disposer's note of when each
  temporary container went empty; and the pause recordings — the sites seen while
  the toolbar button has routing paused, with the container each would have gone
  to. storage.sync holds a mirror of the config text only; see WHERE DATA GOES.
- webNavigation — a "view-source:" load reaches webRequest wearing the INNER url,
  so the blocking listener would reopen it elsewhere and lose the wrapper.
  onBeforeNavigate is the only event naming the view-source: url. Observed only.
- notifications — one toast, when a navigation carries a request body:
  tabs.create can only issue a GET, so re-opening a POST would drop it. The
  request stays put and the user is told which container it would have used.

CONTENT SCRIPTS

The config has an optional "scripts" key; src/engine/script-injector.ts passes
that string to contentScripts.register(). The code comes only from the user's own
storage.local config, never the network: no eval, no new Function, no remote
code. The shipped default has no "scripts" entries.

WHERE DATA GOES

No server: src/ contains no fetch, XMLHttpRequest or sendBeacon call, so nothing
reaches the author or any third party.

One thing leaves the machine. src/extension/config-sync.ts writes the config text
into storage.sync, so Firefox carries it over the user's own Firefox Account —
end-to-end encrypted, between their machines only. It has no toggle; a profile
with no account signed in keeps it locally. Nothing else is published there: the
pause recordings and the empty-since notes stay in storage.local.
